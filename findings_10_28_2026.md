# Findings, 10/28/2026: can Kumo Relational (RFM) win the MSK Kaggle challenge?

Goal: improve Kumo Relational as far as possible and see whether it can beat 1st place on the Kaggle stage-2 leaderboard (log loss 2.030; guessing 1/9 for every class scores 2.197).

**Ground rules.** Every choice was made on 5-fold cross-validation (CV) on the 3,321 training rows. The final recipe was fixed in code (`msk_final_v2.py`) before stage-1 or stage-2 was scored. Each was then scored once. The stage-2 labels had already been seen in a dry run on 10/27, so nothing is tuned on them. Nothing was submitted to Kaggle. All compute ran on the Lambda A100.

Metric throughout: multi-class log loss, lower is better.

## Round 1: fine-tuning settings, measured inside CV

Fine-tuning is redone inside every fold, starting from the pretrained weights and using only that fold's training rows (`msk_cv_kumo.py`).

| Kumo configuration | CV log loss |
|---|---|
| Pretrained, no fine-tuning | 0.840 ± 0.042 |
| Fine-tuned 200 steps, lr 1e-5 | 0.809 |
| Fine-tuned 200 steps, lr 3e-5 | 0.809 |
| Fine-tuned 400 steps, lr 1e-5 | 0.807 |
| Fine-tuned 400 steps, lr 3e-6 | **0.806** |
| Fine-tuned 200 steps, 32 estimators | 0.808 |
| 3 fine-tuned copies averaged | 0.806 |

- **Fine-tuning helps in every fold,** by about 0.03 on average.
- **The exact settings barely matter.** 400 steps at lr 3e-6 was kept.

## Round 2: label-sharing features

These features give each row the class mix of other labeled mutations in the same gene, and in the same article.

- **The first version leaked.** It was computed leaving out only the row itself. That makes a row's own class look *rarer* in its group than it does for its neighbours, and both models learned that inverted signal. XGBoost went to 1.04; fine-tuned Kumo went to 1.93.
- **Fixed with out-of-fold encoding,** the features no longer break anything, but they still hurt:

  | | Without | With |
  |---|---|---|
  | Kumo, fine-tuned | 0.806 | 0.840 |
  | XGBoost | 0.861 | 0.870 |

- **Dropped.** The 0.861 XGBoost baseline here uses the same competition text build as Kumo. It replaces the earlier 0.854 baseline, which used text features fit on training rows only.

## Round 3: holding out whole genes, as a stand-in for stage-2

Every gene's rows sit in a single fold, so each fold is tested on genes the model has never seen.

| Model | Gene-held-out log loss | AUC |
|---|---|---|
| Kumo pretrained | 1.434 | 0.76 |
| Kumo fine-tuned | **1.408** | 0.78 |
| XGBoost | 1.476 | 0.75 |

- **Unseen genes are much harder,** but both models stay well above chance, and Kumo still leads.
- **Hedging, chosen on out-of-fold predictions** (`msk_hedge.py`), means blending toward uniform or the training class mix, or tempering the probabilities.
  - Under both standard and gene-held-out CV, the best amount for Kumo is **none** (blend weight 0, temperature ≈ 1.0). XGBoost wants a tiny amount (temperature 0.9).
  - So the honest recipe uses **no hedging**.

## Round 4: variant-specific text

Many articles discuss dozens of mutations, so a summary of the whole article blurs them together. The new features (`msk_features.add_variant_text`) keep only the sentences that mention the row's own mutation. That means the exact variant (e.g. "V600E") or the same residue (e.g. "V600"). For non-point variants such as "Truncating Mutations", they keep sentences that mention the gene together with the variant's keyword. TF-IDF is then reduced to 50 components. About 80% of rows have such sentences.

| Model | Standard CV | Gene-held-out CV |
|---|---|---|
| Kumo fine-tuned + variant text | **0.785** (from 0.806) | 1.412 (from 1.408) |
| Kumo pretrained + variant text | 0.817 (from 0.840) | 1.427 |
| XGBoost + variant text | 0.837 (from 0.861) | 1.480 (from 1.476) |

- **Variant text helps both models by about 0.02–0.025 on standard CV.**
- **It does nothing on unseen genes.** It helps tell apart mutations *within* a known gene; it doesn't help with new genes.

## Final, pre-registered evaluation (`msk_final_v2.py`)

Recipe:
- **Features:** competition build plus variant text.
- **Kumo:** fine-tuned 400 steps at lr 3e-6.
- **XGBoost:** 100 Optuna trials on the training rows.
- **No hedging.**
- **For stage-2:** both models are refit on training + stage-1 rows.

| Set | Model | Log loss | Accuracy | AUC |
|---|---|---|---|---|
| Stage-1 (368) | **Kumo fine-tuned + variant text** | **0.667** | 0.753 | 0.936 |
| Stage-1 (368) | XGBoost + variant text | 0.710 | 0.753 | 0.948 |
| Stage-2 (125) | Kumo fine-tuned + variant text | 3.433 | 0.216 | 0.525 |
| Stage-2 (125) | XGBoost + variant text | 3.275 | 0.200 | 0.568 |
| Both | uniform 1/9 | 2.197 | | 0.500 |

- **Stage-1 confirms the CV ranking.** Kumo beats XGBoost by 0.043, matching yesterday's fine-tuned margin. XGBoost improved from 0.733 to 0.710 with the variant text; Kumo landed at 0.667, about the same as yesterday's best seed (0.666). Accuracy is tied; XGBoost still ranks classes slightly better (AUC).
- **Stage-2 is unchanged from yesterday:** both models are far worse than guessing, with ranking near chance (AUC 0.53–0.57). Better CV and stage-1 scores did not carry over at all.

## Can RFM win the leaderboard?

**Not legitimately, with anything tried so far.**

- **No honest signal points to heavy hedging.** Uniform guessing beats every model on stage-2, and the only way to beat it is heavy hedging (about 0.8 weight on uniform, per yesterday's hindsight diagnostic). Our stand-in for stage-2, gene-held-out CV, says *no* hedging. We already know stage-2's answer, so choosing a hedge now would be tuning on the test set.
- **Even the hindsight-best hedge (≈2.16) misses 1st place (2.030).**
- **Stage-2's difficulty is not mainly unseen genes.** 87% of its genes appear in training, yet scores there are far worse than on fully unseen genes in CV (≈3.3 vs ≈1.41). Its class mix is very different (e.g. class 2 is 42% vs 14% in training, class 7 is 4% vs 29%), and its labels may be noisier. Nothing in the training text reveals that.
- **Only 14 of the original teams beat uniform on this set.**

## Conclusions

1. **Kumo Relational, fine-tuned for a few minutes on one GPU, is the best model here on every legitimate benchmark:**
   - standard CV: 0.785 vs 0.837
   - gene-held-out CV: 1.41 vs 1.48
   - stage-1: 0.667 vs 0.710
2. **Its probabilities are well calibrated without hedging,** even on unseen genes.
3. **The stage-2 leaderboard set can't tell these models apart,** and isn't a meaningful target given what we know about it.

## Files

- **Scripts:**
  - `msk_cv_kumo.py`: Kumo CV harness, with `--gene-folds` and `--variant-text`; saves out-of-fold predictions.
  - `msk_xgb.py`: adds `--comp-features`, `--variant-text`, `--gene-folds`; saves per-fold predictions.
  - `msk_hedge.py`: chooses hedging from out-of-fold predictions.
  - `msk_features.py`: label-sharing and variant-text features.
  - `msk_final_v2.py`: the pre-registered final evaluation.
  - `run_round1.sh` … `run_round4.sh`: the experiment queues.
- **Logs:**
  - `logs/lambda/cv_kumo.jsonl`: every Kumo CV result.
  - `logs/lambda/*_folds.log`: XGBoost CV.
  - `logs/lambda/final_v2.log`: the final evaluation.
- **Submissions:** `data/msk/submissions/v2_kumo.csv` and `v2_xgboost.csv` (986 rows each). **Not uploaded.**
